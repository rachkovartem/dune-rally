# src/net — Network / Interpolation Module

## Purpose
Client-side networking utilities. Provides a Colyseus connection wrapper for joining an arena room, a snapshot-based transform interpolation helper for smooth rendering of remote players between server ticks, and a `PlayerViews` manager that keeps Three.js meshes in sync with remote player state. `connection.ts` and `playerViews.ts` are browser-only; `interpolation.ts` is pure and safe to import from Node.

## Files

### connection.ts
- `interface NetPlayer { name: string; x: number; y: number; z: number; qx: number; qy: number; qz: number; qw: number }` — live player state mirrored from the server's Colyseus schema.
- `interface Connection { sessionId: string; seed: number; sendInput(i: InputMsg): void; onAdd(cb: (id: string, p: NetPlayer) => void): void; onRemove(cb: (id: string) => void): void; players(): Map<string, NetPlayer> }` — handle returned to the caller after a successful join.
- `async function connectToArena(url: string, name: string): Promise<Connection>` — creates a `colyseus.js` `Client`, calls `joinOrCreate('arena', { name })`, wires `state.players.onAdd/onRemove` listeners that keep an internal `Map<string, NetPlayer>` up to date and fire registered callbacks, and returns a `Connection`.
- Depends on: `colyseus.js` (Client SDK), `InputMsg` from `shared/protocol`.

### interpolation.ts
- `interface Snapshot { t: number; x: number; y: number; z: number; qx: number; qy: number; qz: number; qw: number }` — a timestamped world-space position + quaternion received from the server.
- `type Transform = Omit<Snapshot, 't'>` — position + quaternion without the timestamp; used as the sampling result.
- `class TransformBuffer` — ring buffer of up to `MAX_HISTORY` (30) snapshots.
  - `push(s: Snapshot): void` — appends the snapshot; evicts the oldest when the buffer is full.
  - `sample(renderTime: number): Transform` — returns the interpolated transform for the given render timestamp:
    - Zero snapshots → identity `{ x:0, y:0, z:0, qx:0, qy:0, qz:0, qw:1 }`.
    - Before or at the first snapshot / only one snapshot → clamp to first.
    - After or at the last snapshot → clamp to last.
    - Between two snapshots → linear-interpolate position (lerp), shortest-path normalised-lerp (nlerp) quaternion.
- Quaternion nlerp: flip sign of `b` when `dot(a,b) < 0` (shortest-arc), then component-wise lerp and re-normalise.

### interpolation.test.ts
- Vitest unit tests (pure; no DOM or module mocks required).
- Cases: midpoint linear interpolation (`x` from 0→10 at t=50ms), before/after clamping, single-snapshot identity.

### playerViews.ts
- `class PlayerViews` — manages a collection of Three.js meshes representing remote players; keeps each mesh's transform in sync with buffered server snapshots.
  - `constructor(scene: THREE.Scene, world: RAPIER.World, groundHeight?: (x: number, z: number) => number)` — `world` is only read: each remote wheel casts a ray down against **fixed** colliders (a filter predicate on `collider.parent()`, not `QueryFilterFlags`, whose JS values in rapier3d-compat 0.13.1 do not match the engine). When the ray finds nothing (no collider is built that far from the local car), `groundHeight` gives the drawn ground; out of reach → the wheel hangs at its resting length.
  - `add(id: string, carId: CarId): void` — creates that car's mesh via `buildBuggyMesh(carId)`, adds it to the scene, and registers a fresh `TransformBuffer`; the view keeps its `carId`. No-op if `id` is already tracked.
  - `remove(id: string): void` — removes the mesh from the scene and deletes the entry; no-op if `id` is unknown.
  - `pushState(id: string, p: NetPlayer, t: number): void` — pushes a timestamped snapshot `{ t, x, y, z, qx, qy, qz, qw }` into the player's `TransformBuffer`; no-op if player is unknown.
  - `update(renderTime: number): void` — iterates all views, calls `buffer.sample(renderTime)` for each, and applies the resulting position/quaternion to the group.
  - `group(id: string): THREE.Group | undefined` — returns the Three.js group for a given player id, or `undefined` if not tracked.
- Depends on: `buildBuggyMesh` from `../render/buggyMesh`, `TransformBuffer` from `./interpolation`, `NetPlayer` type from `./connection`, `CarId` type from `../vehicle/cars`, `three`.

## Key Constraints

### connection.ts
- Imports `Client`/`Room` from `colyseus.js` (client SDK) — Colyseus is intentional here.
- Browser-only: must not be imported by the server or unit tests that run under Node without a DOM.

### interpolation.ts
- **Pure function**: `renderTime` is always passed in by the caller — never call `Date.now()` or `performance.now()` inside interpolation.ts.
- No external dependencies beyond standard TypeScript types.
- No three.js, no Colyseus, no DOM (safe to import from both the browser client and unit tests).

### playerViews.ts
- **Browser-only**: imports `three` and `../render/buggyMesh` (which in turn imports three.js and DOM-bound render utilities). Must not be imported by the server or Node-based unit tests.
- Never calls `Date.now()` / `performance.now()` internally — the caller passes `renderTime` to `update()`.

## Integration Pattern
The caller is responsible for maintaining a clock offset (e.g. `serverTime - interpolationDelay`):
```ts
buffer.push({ t: serverTimestamp, ...serverTransform });
const pose = buffer.sample(renderTime); // renderTime = now - interpolationDelay
mesh.position.set(pose.x, pose.y, pose.z);
// apply quaternion to mesh separately
```
