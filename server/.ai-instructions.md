# server — DUNE RALLY Server Module

## Purpose
Colyseus multiplayer game server. Handles WebSocket connections, room lifecycle, authoritative game state, and broadcasts schema patches to clients.

## Files

### index.ts
- Entry point. Constructs a `Server` from `@colyseus/core` with an explicit `WebSocketTransport` from `@colyseus/ws-transport` (NOT the umbrella `colyseus` package — its ESM build does not re-export these under tsx).
- Pattern: `new Server({ transport: new WebSocketTransport({ server: createServer() }) })`.
- Reads `SERVER_PORT` from `shared/protocol`.
- Registers `ArenaRoom` under the `"arena"` room name via `gameServer.define('arena', ArenaRoom)`.

### ArenaRoom.ts
- Exports `class ArenaRoom extends Room<ArenaState>`.
- **`async onCreate(options: { seed?: number })`** — resolves seed as `options.seed ?? dailySeed('2026-06-19')`, calls `this.setState(new ArenaState())`, sets `state.seed`, bootstraps `await ArenaSim.create(seed)`, configures patch rate (`1000 / PATCH_HZ` ms) and sim interval (`1000 / TICK_HZ` ms), registers an `'input'` message handler that calls `sim.setInput(client.sessionId, sanitizeInput(msg))`.
- **`onJoin(client, options: { name?: string })`** — calls `sim.addPlayer(client.sessionId)`, creates a new `PlayerState`, truncates player name to 24 characters (`(options?.name ?? 'rider').slice(0, 24)`), inserts it into `state.players`.
- **`onLeave(client)`** — calls `sim.removePlayer(client.sessionId)` and deletes the entry from `state.players`.
- **`private tick()`** — calls `sim.step()`, iterates `sim.playerIds()`, reads each `sim.transform(id)`, and writes x/y/z/qx/qy/qz/qw into the corresponding `PlayerState` entry.
- Default seed: `dailySeed('2026-06-19')` from `src/world/seed.ts`.
- Name truncation: names longer than 24 characters are silently truncated via `.slice(0, 24)`.

### state.ts
- Exports `PlayerState` (extends `Schema`) and `ArenaState` (extends `Schema`).
- Uses the non-decorator `defineTypes(Class, typeMap)` API from `@colyseus/schema`.
- `PlayerState` fields: `x, y, z, qx, qy, qz, qw` (all `'number'`), `name` (`'string'`).
- `ArenaState` fields: `seed` (`'number'`), `players` (`{ map: PlayerState }`).
- Default values: position components = 0, `qw = 1`, `name = ''`, `seed = 0`.

### state.test.ts
- Vitest unit tests for `ArenaState` and `PlayerState`.
- Verifies field round-trips and `MapSchema` set/get semantics.

### arenaSim.ts
- Exports `interface PlayerTransform { x, y, z, qx, qy, qz, qw: number }` and `class ArenaSim`.
- `ArenaSim` is the authoritative server-side physics simulation for the arena.
- **`static async create(seed: number): Promise<ArenaSim>`** — must call `await RAPIER.init()` first (WASM bootstrap requirement). Creates a `RAPIER.World` with gravity `-WORLD_GRAVITY` (`shared/drivetrain.ts`, the real 9.81 m/s², the same constant the client world, the bench and the tyre normal force use) and `timestep = 1/60`. Builds only the chunks within `SPAWN_PREBUILD_RADIUS` (2, so 5 × 5) of `SPAWN`, clipped to `[0, WORLD_CHUNKS)`. Every other chunk is built on demand by the collider streamer (below). A chunk build = `generateChunkHeights` → `addChunkCollider` (a Rapier heightfield, `src/physics/physicsWorld.ts`) + `addFeatureColliders(featuresInChunk(cx, cz))`.
- **Collider streaming** — `ColliderStreamer` (`colliderStreamer.ts`) over the demand from `shared/chunkDemand.ts`, options `SERVER_CHUNK_STREAMING` (`mustRadius 1`, `wantRadius 2`, `lookAheadSeconds 1.5`, `buildBudgetPerTick 1` per `step()` = 2 per 30 Hz room tick). `step()` calls `streamer.update(cars)` first: every missing chunk in the 3 × 3 around a car is built in the same step, then at most the budget of the 5 × 5 around the car plus the 3 × 3 around `position + velocity × 1.5 s`, nearest first. Built chunks are never removed (the map is finite; a heightfield chunk is ~22 KB).
- **`builtChunkCount(): number`** — chunks with a server collider so far.
- **`teleportPlayer(id, x, z, lift, { vx, vz })`** — moves a car to `(x, height + lift, z)` with a flat velocity and no spin (tools and tests); throws for an unknown id.
- **`addPlayer(id: string): void`** — spawns a buggy via `createVehiclePhysics` at a deterministic grid position (`32 + (n%4)*24`, terrain height + 4, `32 + floor(n/4)*24`).
- **`setInput(id: string, input: InputMsg): void`** — stores the latest `InputMsg` for a player.
- **`removePlayer(id: string): void`** — removes the rigid body from the world and deletes the player entry.
- **`step(): void`** — streams colliders for the current car positions, applies each player's stored input via `vehicle.applyInput`, advances `world.step()`, then calls `vehicle.update(world.timestep)` for each player.

### colliderStreamer.ts
- `interface ChunkColliderPort { build(chunk): void }` — the side that really adds colliders (ArenaSim).
- `class ColliderStreamer(port, options)` — `update(cars)`, `ensureBuilt(chunk)` (used for the spawn prebuild), `isBuilt(chunk)`, `builtCount()`. A chunk is marked built only after `port.build` returns; a throwing build is rethrown and retried on the next update. Nothing is ever unloaded.
- Pure demand lives in `shared/chunkDemand.ts`: `chunkDemand(cars, options) → { must, want }` (`want` sorted nearest-first, no duplicates, excludes `must`, indices clamped to the world; throws on non-finite car values or bad options).
- **`transform(id: string): PlayerTransform | undefined`** — reads position (`body.translation()`) and orientation (`body.rotation()`) from the Rapier rigid body.
- **`playerIds(): string[]`** — returns the list of currently tracked player IDs.
- Does NOT import three.js or any browser globals; safe to run in Node.js.

### arenaSim.test.ts
- Vitest unit tests for `ArenaSim`.
- **Case 1 — physics settle + drive**: Creates a sim with seed 123, spawns player `'p1'`, runs 120 idle steps (throttle=0) to let the vehicle settle on terrain, asserts `rest.y` is a finite number, then runs 180 throttle steps and asserts the vehicle has moved more than 1 unit in the XZ plane.
- **Case 2 — player lifecycle**: Creates a sim with seed 7, adds players `'a'` and `'b'`, asserts `playerIds()` returns both (sorted), removes `'a'`, asserts only `'b'` remains, and asserts `transform('a')` returns `undefined`.

## Naming Conventions
- Room name: `"arena"` (lowercase string, single source of truth in ArenaRoom definition).
- Default seed: `dailySeed('2026-06-19')` from `src/world/seed.ts`.
- Schema class names: `<Entity>State` pattern (e.g. `PlayerState`, `ArenaState`).

## Key Constraints
- Import `Server` and `Room` from `@colyseus/core`; import `WebSocketTransport` from `@colyseus/ws-transport`.
- Use `defineTypes(...)` (non-decorator API) — decorators require `experimentalDecorators` which is off.
- The server MUST NOT import anything that pulls in three.js or `window` (no `src/render/*`, no `src/vehicle/buggy.ts`).
- Shared constants (`SERVER_PORT`, `TICK_HZ`, `PATCH_HZ`) live in `shared/protocol.ts`. The world size (`WORLD_SIZE`, `WORLD_CHUNKS`) belongs to the world and lives in `src/world/worldDef.ts`.
- World constants (`CHUNK_SIZE`, `CHUNK_RES`) stay in `src/world/chunk.ts`; import them directly when needed.
- Pure modules (`src/world/*`, `src/physics/physicsWorld.ts`, `src/vehicle/vehicleConfig.ts`) are safe to import from the server because they have no browser globals.
- No `Date.now()` or `Math.random()` in pure logic; runtime/network timing uses `performance.now()`/`Date.now()` only in glue code (room tick, interpolation clock), never inside pure functions.

## Tech Stack
