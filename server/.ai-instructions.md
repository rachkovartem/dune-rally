# server — DUNE RALLY Server Module

## Purpose
Colyseus multiplayer game server. Handles WebSocket connections, room lifecycle, authoritative game state, and broadcasts schema patches to clients.

## Files

### index.ts
- Entry point. Constructs a `Server` from `@colyseus/core` with an explicit `WebSocketTransport` from `@colyseus/ws-transport` (NOT the umbrella `colyseus` package — its ESM build does not re-export these under tsx).
- Pattern: `new Server({ transport: new WebSocketTransport({ server: createServer() }) })`.
- Reads `SERVER_PORT` from `shared/protocol`.
- Registers `ArenaRoom` under the `"arena"` room name via `gameServer.define('arena', ArenaRoom)`.
- Sets `matchMaker.controller.exposedMethods = ['joinOrCreate', 'reconnect']`: a client cannot call `create`/`join`/`joinById`, so a new room opens only when every room is full.

### ArenaRoom.ts
- Exports `class ArenaRoom extends Room<ArenaState>`.
- **`async onCreate()`** — ignores the join options (they come from a client): claims one of `MAX_ARENA_ROOMS` (4) process-wide slots (`arenaRoomSlots`, `roomSlots.ts`; none left → `ServerError`, the join fails), sets `state.seed = ARENA_WORLD_SEED` (`config.ts`, `dailySeed('2026-06-19')`), bootstraps `await ArenaSim.create(ARENA_WORLD_SEED)`, configures patch rate (`1000 / PATCH_HZ` ms) and sim interval (`1000 / TICK_HZ` ms), and registers the four message handlers through `onLimitedMessage` (below). The slot is released in `onDispose` (or at once when the world build throws).
- **`onJoin(client, options: unknown)`** — `sanitizeJoinOptions(options)` (`shared/protocol.ts`: `sanitizePlayerName` — string only, control characters removed, trimmed, at most 24 code points, else `'rider'`; `sanitizeCarId`), takes `sim.nextFreeSpawnSlot()`, calls `sim.addPlayer`, creates the `PlayerState` with name, car and `spawnSlot`, **then** inserts it into `state.players`, so the client's first patch already carries the slot.
- **Message rate limit** (`messageRateLimit.ts`, `MESSAGE_RATE_LIMIT`) — one `MessageRateLimiter` per client counts `input`, `resetCar`, `pose` and `selectCar`: 60 a second sustained (burst 60), of which `input` cannot use the last 10 (so a pose or an R always gets through); over budget → the message is dropped; above 400 a second → `client.leave(MESSAGE_FLOOD_CLOSE_CODE)` (4429).
- **`'pose'` message** (`POSE_MESSAGE`, plan v3 S1-X) — `sanitizePose(msg)` (`shared/protocol.ts`: every field a finite number, position within 1e5 m, speed ≤ 300 m/s, quaternion length 0.9–1.1 then normalised; otherwise `null`, and the message is dropped) → `trustedPose` (`poseTrust.ts`: rejected when further from the server copy than `max(POSE_SNAP_DISTANCE, 1.5 × 1.25 × topSpeed × seconds since the last accepted pose) + 5 m`; velocity capped at `1.25 × topSpeed` of the player's car) → `sim.applyClientPose(sessionId, pose)`. The client sends its own car's pose at `POSE_HZ` (10).
- **Crash guards** — `onUncaughtException` logs a throw from onCreate/onJoin/onLeave/a message handler/the tick and does not rethrow, so the process stays up. `broadcastPatch` and `sendFullState` are overridden: a state the encoder cannot encode closes that room (`ROOM_BROKEN_CLOSE_CODE`, 4500) instead of reaching the process.
- **`onLeave(client)`** — calls `sim.removePlayer(client.sessionId)` and deletes the entry from `state.players`.
- **`private tick()`** — calls `sim.step()`, iterates `sim.playerIds()`, reads each `sim.transform(id)`, and writes x/y/z/qx/qy/qz/qw into the corresponding `PlayerState` entry.
- World seed: `ARENA_WORLD_SEED` (`dailySeed('2026-06-19')`) from `config.ts`, never from the client.

### state.ts
- Exports `PlayerState` (extends `Schema`) and `ArenaState` (extends `Schema`).
- Uses the non-decorator `defineTypes(Class, typeMap)` API from `@colyseus/schema`.
- `PlayerState` fields: `x, y, z, qx, qy, qz, qw` (all `'number'`), `name`, `carId` (`'string'`), `spawnSlot` (`'number'`, `-1` until the server gives the player a slot).
- `ArenaState` fields: `seed` (`'number'`), `players` (`{ map: PlayerState }`).
- Default values: position components = 0, `qw = 1`, `name = ''`, `seed = 0`.

### state.test.ts
- Vitest unit tests for `ArenaState` and `PlayerState`.
- Verifies field round-trips and `MapSchema` set/get semantics.

### arenaSim.ts
- Exports `interface PlayerTransform { x, y, z, qx, qy, qz, qw: number }` and `class ArenaSim`.
- `ArenaSim` is the authoritative server-side physics simulation for the arena.
- **`static async create(seed: number): Promise<ArenaSim>`** — must call `await RAPIER.init()` first (WASM bootstrap requirement). Creates a `RAPIER.World` with gravity `-WORLD_GRAVITY` (`shared/drivetrain.ts`, the real 9.81 m/s², the same constant the client world, the bench and the tyre normal force use) and `timestep = 1/60`. Builds only the chunks within `SPAWN_PREBUILD_RADIUS` (2, so 5 × 5) of `SPAWN` (the Suidhek spawn rise, Klipfontein 3072 m map), clipped to `[0, WORLD_CHUNKS)`. Every other chunk is built on demand by the collider streamer (below). A chunk build = `generateChunkHeights` → `addChunkCollider` (a Rapier heightfield, `src/physics/physicsWorld.ts`) + `addFeatureColliders(featuresInChunk(cx, cz))`.
- **Collider streaming** — `ColliderStreamer` (`colliderStreamer.ts`) over the demand from `shared/chunkDemand.ts`, options `SERVER_CHUNK_STREAMING` (`mustRadius 1`, `wantRadius 2`, `lookAheadSeconds 1.5`, `buildBudgetPerTick 1` per `step()` = 2 per 30 Hz room tick). `step()` calls `streamer.update(cars)` first: every missing chunk in the 3 × 3 around a car is built in the same step, then at most the budget of the 5 × 5 around the car plus the 3 × 3 around `position + velocity × 1.5 s`, nearest first. Built chunks are never removed (the map is finite; a heightfield chunk is ~22 KB).
- **`builtChunkCount(): number`** — chunks with a server collider so far.
- **`teleportPlayer(id, x, z, lift, { vx, vz })`** — moves a car to `(x, height + lift, z)` with a flat velocity and no spin (tools and tests); throws for an unknown id.
- **`nextFreeSpawnSlot(): number`** — `lowestFreeSlot(slots in use, SPAWN_SLOT_COUNT)` (exported pure helper: lowest free slot; all 12 taken → `used.size % count`). A slot is freed when its player is removed.
- **`addPlayer(id, carId, spawnSlot): void`** — builds the car at `spawnPoseFor(slot)` (`src/world/worldDef.ts`: 3 rows × 4, 5 m apart, 7 m between rows, front row 30 m south of the farm gate), `SPAWN_LIFT` (2 m) above `terrainSurfaceHeight`, rotation `rotationForYaw(pose.yaw)` (north). The client builds its own car at the same pose. Throws for an id already in the arena.
- **Border safety net** — at the start of every `step()`, `borderEscapeTarget(x, y, z, height)` (`src/world/borderSafety.ts`, the same function the client runs on its own car) is checked per car; a car outside the map, or more than 40 m past the face foot and above the crest, is put on the nearest road point (`nearestRoadPose`), standing still, facing along the road into the valley.
- **`applyClientPose(id, pose): boolean`** — snaps the server copy to the driver's pose (position, rotation, velocity; spin cleared) when the gap is over `POSE_SNAP_DISTANCE` (2 m) or `POSE_SNAP_ANGLE` (20°, full rotation angle); returns whether it snapped. Unknown id → `false`.
- **`setInput(id: string, input: InputMsg): void`** — stores the latest `InputMsg` for a player and restarts its input age. A client that sends nothing for `INPUT_TIMEOUT_SECONDS` (0.5 s — a hidden or frozen tab) gets `releasedInput(last)`: throttle, brake and steer 0, traction control and drive mode kept, so its copy coasts instead of driving on the last pedals.
- **`removePlayer(id: string): void`** — removes the rigid body from the world and deletes the player entry.
- **`step(): void`** — runs the border safety net, streams colliders for the current car positions, applies each player's stored input via `vehicle.applyInput`, advances `world.step()`, then calls `vehicle.update(world.timestep)` for each player.

### colliderStreamer.ts
- `interface ChunkColliderPort { build(chunk): void }` — the side that really adds colliders (ArenaSim).
- `class ColliderStreamer(port, options)` — `update(cars)`, `ensureBuilt(chunk)` (used for the spawn prebuild), `isBuilt(chunk)`, `builtCount()`. A chunk is marked built only after `port.build` returns; a throwing build is rethrown and retried on the next update. Nothing is ever unloaded.
- Pure demand lives in `shared/chunkDemand.ts`: `chunkDemand(cars, options) → { must, want }` (`want` sorted nearest-first, no duplicates, excludes `must`, indices clamped to the world; throws on non-finite car values or bad options).
- **`transform(id: string): PlayerTransform | undefined`** — reads position (`body.translation()`) and orientation (`body.rotation()`) from the Rapier rigid body.
- **`playerIds(): string[]`** — returns the list of currently tracked player IDs.
- Does NOT import three.js or any browser globals; safe to run in Node.js.

### arenaSim.test.ts
- Vitest unit tests for `ArenaSim`.
- **Case 1 — physics settle + drive**: Creates a sim with seed 123, spawns player `'p1'`, runs 120 idle steps (throttle=0) to let the vehicle settle on terrain, asserts `rest.y` is a finite number, then runs 180 throttle steps and asserts the vehicle has moved more than 1 unit in the XZ plane.
- **Case 2 — player lifecycle**: Creates a sim with seed 7, adds players `'a'` and `'b'`, asserts `playerIds()` returns both (sorted), removes `'a'`, asserts only `'b'` remains, and asserts `transform('a')` returns `undefined`.

## Naming Conventions
- Room name: `"arena"` (lowercase string, single source of truth in ArenaRoom definition).
- World seed: `ARENA_WORLD_SEED` from `config.ts`.
- Schema class names: `<Entity>State` pattern (e.g. `PlayerState`, `ArenaState`).

## Key Constraints
- Import `Server` and `Room` from `@colyseus/core`; import `WebSocketTransport` from `@colyseus/ws-transport`.
- Use `defineTypes(...)` (non-decorator API) — decorators require `experimentalDecorators` which is off.
- The server MUST NOT import anything that pulls in three.js or `window` (no `src/render/*`, no `src/vehicle/buggy.ts`).
- Shared constants (`SERVER_PORT`, `TICK_HZ`, `PATCH_HZ`) live in `shared/protocol.ts`. The world size (`WORLD_SIZE`, `WORLD_CHUNKS`) belongs to the world and lives in `src/world/worldDef.ts`.
- World constants (`CHUNK_SIZE`, `CHUNK_RES`) stay in `src/world/chunk.ts`; import them directly when needed.
- Pure modules (`src/world/*`, `src/physics/physicsWorld.ts`, `src/vehicle/vehicleConfig.ts`) are safe to import from the server because they have no browser globals.
- No `Date.now()` or `Math.random()` in pure logic; runtime/network timing uses `performance.now()`/`Date.now()` only in glue code (room tick, interpolation clock), never inside pure functions.
